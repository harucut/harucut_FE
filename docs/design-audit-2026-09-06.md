# 디자인 검수 — 2026-09-06

웹 21개 라우트를 **앱 셸 조건으로 실제로 띄워 찍고** 잰 뒤, 소스와 대조해 고쳤다.
이 문서는 「무엇을 어떻게 봤나」와 「고치지 않고 남긴 것」을 갖는다 — 고친 것은 커밋이 말한다.

- **세트 5개**: 안드로이드 셸(Pixel 5, 393×851, 다크·라이트) · iOS 셸(iPhone 13, 390×844, WebKit, 다크·라이트) · 데스크톱(1280×900, 다크).
  셸은 `window.__HARUCUT_NATIVE__` + 가짜 `ReactNativeWebView.postMessage`(id 있는 메시지에 `ok:true` 로 답함) + UA 토큰 `harucutapp/…` 으로 흉내냈다.
- **화면 26장/세트**: 공개 11 · 회원 6 · 비회원 진입 1 · 흐름 8(촬영·비회원 촬영·불러오기 빈/채움·사진 선택 0/4장·결과·에디터).
  회원은 `tests/e2e/fixtures/apiStub.ts` 로 API 를 막았다 — 기록·프레임은 가짜 데이터다.
- **측정값**(화면마다 JSON): 44px 미만 탭 타깃, 12px 미만 글자, 첫 화면 안의 초록 요소 수, 가로 넘침, 라벨 없는 입력, 치수 없는 `<img>`, 랜드마크, 하단 고정 요소.
- **기준 넷**: `apps/web/DESIGN.md`(우선) · Vercel Web Interface Guidelines · apple-design(움직임·피드백·자간) · taste-skill 안티슬롭 체크. 영문 타이포 규칙(곡선 인용부호·em-dash)은 한국어 UI 에 적용하지 않았다.
- **검수 → 반증**: 6묶음(마케팅·인증·앱 탭·촬영 흐름·에디터·전역/셸)으로 77건을 냈고, 각 건의 스크린샷·JSON·소스 인용을 다시 열어 확인한 것만 고쳤다.

하네스는 저장소에 넣지 않았다(스크래치패드). 다시 만들 때의 요령은 세션 메모리에 있다 — 핵심은 위 다섯 줄이다.

## 가장 큰 발견 — 안전영역

웹은 `env(safe-area-inset-bottom)` 만 5곳에서 쓰고 **top 은 0곳**이었다. 셸은 실패 화면에만 `insets.top` 을 줬다.
안드로이드는 `edgeToEdgeEnabled=true`(prebuild `gradle.properties`)라 WebView 가 상태바 뒤까지 그리는데 크로미움 WebView 는 그 높이를
env 에 주지 않고, iOS 는 react-native-webview 기본값 `contentInsetAdjustmentBehavior=never`(RNCWebViewImpl.m:189)라 스크롤뷰가 비키지 않는다.
→ **모든 화면의 상단(뒤로가기·제목·네비)이 상태바 아래로 들어갔다.** 셸이 `insets.top`(양쪽)·`insets.bottom`(안드로이드)을 비우게 고쳤다
([mobile-shell.md](./mobile-shell.md) 표 「안전영역」). **실기기 확인은 아직이다** — iPhone 노치 기기와 Android 15(3버튼·제스처)에서 촬영 화면 뒤로가기와 홈 탭바를 본다.

## 소스로 확정한 것들 (고쳤다)

- **Konva 변형 핸들이 0.75px** — Transformer 는 부모 스케일을 보정하지 않는데(`Transformer.js update()`) 스테이지가 0.075 배라 기본 10px 핸들이 화면에서 0.75px 이었다. 스케일로 나눠 24px 로.
- **터치 규칙이 아이콘 버튼을 타원으로** — `pointer:coarse` 가 `min-height:44` 만 주고 `a` 와 `h-[30px]`·`h-6` 버튼에는 `min-width` 를 안 줘 30×44·24×44 세로 타원이 됐다(기록 삭제, 업로드 ✕, PageHeader 뒤로가기).
- **`[class*="bg-white/…"]` 부분일치 !important 매핑** — `hover:bg-white/[0.07]` 까지 상시 덮어 라이트 테마 랜딩 네비가 hover 에 흰 알약+흰 글자. 블록을 걷어내고 실사용 두 곳을 토큰으로.
- **theme-color 가 `#0B0B0C` 고정** — 라이트 테마 브라우저 UI 가 검게. media 분기 + 부트스트랩·테마 적용 시 메타 동기화. 딥다크 고정 무대(랜딩·기능)는 머무는 동안 셸·메타에 '다크' 를 알린다.
- **전역 터치 기본값 없음** — `-webkit-tap-highlight-color`·`touch-action: manipulation` 추가, `.hc-button-*` 에 `:active` 피드백.
- **인증 폼**: 입력 36px·라벨 11px(모바일 16px 강제와 위계 역전) → 44px·13px, 인증 코드 라벨·오류 연결, 약관 줄 44px, 비번찾기 텍스트 버튼 44px.
- **촬영 흐름**: 사진 선택 첫 화면이 미리보기 하나(660px)로 꽉 차던 것, 주 CTA 가 29px 알약이던 것, `#1`+`1` 이중 배지, 색·파일명 입력 라벨, "브라우저가 카메라…"(앱 안), "클릭해서 선택", 셔터 눌림·햅틱.
- **기록**: 카드마다 초록 「저장」(한 화면에 초록 3~5개) → 중립. **홈**: 같은 다이얼로그를 여는 초록이 둘(카드+탭바) → 카드는 중립, 가로 스크롤 첫 카드 잘림(`scroll-px-4`).
- **에디터**: 헤더를 PageHeader 로(제목 h1·44px 뒤로가기·모바일 sticky), 입력 8곳 `hc-input` 포커스 링, 11px 본문 21곳 → 12~13px, `text-zinc-500` 본문 → `--hc-muted`, 배경색 코드에 `#` 접두, 오탈자.
- **마케팅**: 요금제 비교표 `min-w-[520px]` → 폰에서 '베이직' 열이 화면 밖 → 3열 맞춤. 테마 따르는 화면의 헤더 CTA 는 중립(본문 초록에 양보). 랜딩·기능에 `main` 랜드마크.
- **모션**: `transition-all` 4곳 → 속성 명시, `outline-none` 2곳 → 링, 스켈레톤 pulse 도 reduced-motion 에서 멈춤, 로딩 문구 `...` 25곳 → `…`.

## 2차에서 마저 고친 것 (같은 날)

- **테마 정책** — 랜딩·기능만 하드코딩 다크였고 요금제·FAQ·행사·약관은 사용자 테마를 따라, 라이트 사용자가 기능 → 요금제로 가면
  화면이 뒤집혔다. 공개 마케팅 무대 전체를 딥다크 고정으로(`globals.css .hc-stage-dark`, 비로그인 화면), 로그인 뒤 앱 화면은
  사용자 테마. MarketingNav 는 `tone` 대신 `cta`(primary/quiet) 만 갖는다. 정책은 `apps/web/DESIGN.md` 「테마 정책」.
- **요금제** — 눈썹 `PRICING · 요금제` 제거, 무료 카드의 가격 '무료' → '₩0'(이름이 이미 무료), '결제 준비 중' 을 알약이 아닌 상태
  글로, 하단 '시작하기' 는 이 절의 뜻(비회원 촬영)대로 `가입 없이 체험하기`(GuestTrialStartButton) 로. FAQ 눈썹도 제거.
- **결과 화면** — 헤더 설명과 같은 말을 하던 '결과 준비 완료' 카드와 정보 없는 '이미지' 칩을 걷어내고 준비 중일 때만 상태 카드.
  비회원 안내의 중복 다운로드 버튼을 빼고 잠긴 기능 둘은 문장형 버튼 대신 「기록 보관 · 로그인 후」 줄로.
- **에디터** — `window.confirm` 삭제 확인 → `ConfirmDialog`, `alert` 7곳 → 화면 안 인라인 알림(저장 다이얼로그의 숨긴 레이어 안내,
  사진 패널의 실패·제외 안내, 삭제 실패). '배경 제거' 초록 라벨 → muted.
- **Pretendard** — jsdelivr `<link>` 대신 `pretendard` 패키지의 dynamic-subset CSS 를 번들에 넣어 같은 오리진에서 낸다.
- **인증** — 로그인의 '가입 없이 체험하기' 를 주 CTA 와 같은 알약에서 44px 글자 링크로(같은 무게의 알약 다섯 개였다).
  AuthPageShell 을 위 정렬로 고정(비밀번호 찾기만 세로 가운데라 로고가 115px 뛰던 것).
- **MY** — 모바일 섹션 헤딩이 부제까지 삼키던 것(`aria-label`/`aria-describedby`), 아바타 이니셜 폴백 초록 → 중립.
- **이미지** — FramePreview 슬롯 img 에 width/height 힌트, 랜딩 히어로 미리보기는 eager.
- **행사 배너** 초록 칩 → 중립(촬영 흐름 첫 화면 초록 넷 → 셋), 기능 화면의 한글 모노 라벨(`촬 영`) → 산세리프 12px,

## 고치지 않고 남긴 것

| 지적 | 왜 남겼나 |
|---|---|
| 촬영 무대 위아래 절반이 빈 어두운 면, 찍은 컷을 볼 곳이 없음 | 촬영 스트립은 최근 「카메라 앱처럼」 커밋에서 **일부러 걷어낸 것**이다. 되살리려면 그 결정을 먼저 뒤집어야 한다 |
| 로그인 라이트에서 로그인 CTA(#16B454)와 네이버(#03A94D)가 비슷한 초록 | 네이버 가이드가 버튼 색을 못박는다. 배치로 풀려면 소셜 묶음을 폼과 더 떨어뜨리는 레이아웃 결정이 필요하다 |
| 마케팅 화면 데모 사진의 실제 치수 | FramePreview 에 슬롯 비율 힌트는 넣었다. 파일 자체 치수는 LCP 측정과 함께 볼 일이다 |
