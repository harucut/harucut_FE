# ADR-0002. 셀 누끼(cellCutouts) 영속화 범위

## 상태

채택 (2026-06-16) / 부분 갱신 (2026-06-28, `b916432`). MVP 범위 한정.

`b916432`로 동영상 기능이 제거되어 영상 출력 경로 서술은 삭제했다. 핵심 결정
(누끼는 클라이언트 시각 효과, 백엔드에 저장하지 않음)은 그대로 유효하다.

## 맥락

프레임 꾸미기(테마 에디터)에 "누끼" 탭이 있다. 4개 칸을 토글하면 해당 칸에
가장자리를 어둡게 하는 비네트 + 녹색 링을 씌워 "배경이 지워진 것처럼" 보이게
한다. 실제 사진 배경을 따내는 세그멘테이션이 아니라, **칸에 거는 클라이언트
전용 시각 효과(MVP)** 다. 상태는 `cellCutouts: boolean[]`로 들고 있다.

- 웹: `apps/web/lib/themeEditorStore.ts`
- 앱: `apps/mobile/store/use-theme-editor-store.ts`

### 현재 저장 흐름

프레임 저장은 다음 두 가지를 남긴다.

1. **합성 미리보기 이미지** — 에디터 미리보기를 캡처해 presigned 업로드
   (`isTemp: false`, `type: 'FRAME'`)로 영구 보관하고 `previewKey`로 참조한다.
   배경/스티커 등 편집 중 임시 자산은 `isTemp: true`로 올렸다가 실제 사용된
   것만 남는다.
2. **프레임 정의** — `frameType`, `background`, `components`(사진/스티커/텍스트)
   를 `createRemoteFrame`/`updateRemoteFrame`로 저장한다.

백엔드 프레임 스키마(`FrameCreateRequest` / `RemoteFrame`)에는 **셀 누끼를
담을 필드가 없다.** 즉 누끼는 정의에 저장되지 않는다.

### 누끼가 출력에 반영되는 지점

- `renderThemePreviewPng` (저장 썸네일) — 컴포넌트 위에 누끼를 그린다.
- `composeFramePng` (실제 다운로드·공유 출력) — 본 PR에서 컴포넌트 렌더 뒤에
  동일한 누끼를 그리도록 보강했다.

두 경로 모두 **호출 시점의 `theme.cellCutouts`** 를 읽는다. 따라서 꾸미기 직후
바로 저장·촬영·업로드하면 누끼가 **이미지에 구워져** 남는다.

## 평가: 현재 로직이 적절한가

"백엔드는 임시 업로드만 거치고 실제 프레임에 들어간(합성된) 이미지만 보관한다"
는 모델은 **MVP 시각 효과에는 적절하다.** 누끼는 결과 이미지에 구워지므로,
사용자가 보는 산출물(썸네일·다운로드·공유)에는 효과가 유지된다.

다만 누끼를 **정의로 저장하지 않기 때문에** 다음 한계가 생긴다.

1. 저장한 프레임을 **다시 열어 편집**하면 누끼 토글이 초기화된다(이미지에는
   남아 있지만 토글 상태는 복원되지 않음).
2. 저장한 프레임을 **나중에 촬영/업로드에 재사용**하면, 정의(`components`)에서
   다시 합성하므로 누끼가 빠진 결과가 나온다. 갓 꾸민 프레임을 즉시 쓰는
   경우에만 누끼가 반영된다.

즉 "결과 이미지에 굽는다"는 현재 로직은 **단발 사용에는 일관**되지만,
**저장→재편집/재사용 시 불일치**가 있다. MVP에서는 허용 가능한 트레이드오프로
판단해 본 ADR 범위를 여기까지로 한정한다.

## 결정

- 누끼는 **클라이언트 시각 효과**로 두고, **결과 이미지에 굽는 것**까지만
  지원한다(썸네일 + composeFrame 출력). 이번 PR에서 이 일관성은 확보했다.
- 셀 누끼를 백엔드 요청에 옵셔널 필드로 보내는 시도(되돌린 커밋
  `b7d6ac6`)는, 백엔드가 미지 필드를 거부하면 **프레임 저장 자체가 깨질**
  위험이 있어 채택하지 않는다. 백엔드 스키마 지원이 선행되어야 한다.

## 완전 영속화가 필요해질 때(후속 과제)

저장→재편집/재사용까지 누끼를 100% 유지하려면 다음이 필요하다.

1. **백엔드 스키마**: 프레임 엔티티에 `cellCutouts: boolean[]`(또는 칸별
   플래그를 담는 JSON 컬럼) 추가, 생성/수정 요청·응답에 포함.
2. **프론트 배선**(프로토타입은 되돌린 커밋 `b7d6ac6` 참고):
   - 앱: `ThemeFrameDraft` / `FrameCreateRequest` / `RemoteFrame` /
     `toCreateFrameRequest` / `toSavedFrame` / `SavedFrame` /
     `selectSavedFrameForTheme`에 `cellCutouts` 추가.
   - 웹: `apps/web/lib/frameApi.ts`의 요청·응답 타입과 매핑,
     `themeEditorStore` 저장/복원에 동일 적용.
3. **재사용 전파**: 저장 프레임을 촬영/업로드에 쓸 때
   `FramePreview`/`CaptureFrameStage`에 `cellCutouts`를 전달해 최종
   미리보기·캡처에도 반영
   (앱: `shoot-screens.tsx`, `upload-screens.tsx`).

이 작업은 **백엔드 필드 추가가 전제**이므로, 백엔드 협의 후 별도 이슈로 진행한다.
