# ADR-0002. 셀 누끼(cellCutouts) 영속화 범위

## 상태

채택(2026-06-16) → **갱신(2026-08-21, `742970a`). 원 결정이 뒤집혔다.**

2026-06 의 결정은 「누끼는 클라이언트 시각 효과이고 백엔드에 저장하지 않는다」였다.
지금은 **저장한다.** 아래 「결정」이 현행이고, 뒤집히기 전 판단은 맨 아래 「경위」에 기록으로만 남겼다.

## 맥락

프레임 꾸미기(테마 에디터)에 「누끼」 탭이 있다. 4개 칸을 토글하면 해당 칸에 가장자리를 어둡게 하는
비네트 + 녹색 링을 씌워 「배경이 지워진 것처럼」 보이게 한다. 실제 사진 배경을 따내는 세그멘테이션이
아니라 **칸에 거는 시각 효과**다. 상태는 `cellCutouts: boolean[]`(4개, 촬영 슬롯 순서)다.

| 무엇 | 어디 |
|---|---|
| 상태·토글·저장·복원 | `apps/web/lib/themeEditorStore.ts` |
| 토글 UI | `apps/web/components/theme/editor/CutoutPanel.tsx` |
| 서버 요청·응답 매핑 | `apps/web/lib/frameApi.ts` |
| 그리는 코드(비회원 출력) | `apps/web/lib/canvas/composeFrame.ts` 의 `drawCellCutouts` |
| 그리는 코드(저장 썸네일) | `apps/web/lib/canvas/renderThemePreview.ts` |

앱에는 대응 파일이 없다. ADR-0003 으로 `apps/mobile` 의 화면·스토어 계층이 통째로 사라져,
누끼를 포함한 모든 편집 화면은 웹 한 벌뿐이다.

## 결정 (2026-08-21 갱신)

### 1. 누끼는 프레임 **정의에 저장한다**

백엔드 스키마에 필드가 있다. 도는 서버의 `/v3/api-docs` 로 확인했다(2026-09-02).

- 요청: `FrameCreateRequest.cellCutouts` — `minItems: 4`, `maxItems: 4`. **보내려면 정확히 4개**여야
  하고, 생략하면 전부 끈 것으로 본다.
- 응답: `FrameResponse.cellCutouts` — 저장할 때 안 보냈으면 전부 `false`.
- 저장 대상은 `POST /api/auth/user/frame` 과 `PUT /api/auth/user/frame/{frameId}` 둘 다이며,
  두 엔드포인트의 요청 본문 스키마는 같은 `FrameCreateRequest` 다.

서버는 컬럼까지 판다 — jar 의 `com/harucut/frame/entity/Frame.class` 에 `cell_cutouts`,
`CellCutoutsConverter`, `normalizeCellCutouts` 가 있다.

> **이름 주의.** `RemoteFrame` 은 백엔드 스키마 이름이 아니다. `apps/web/lib/api-types.ts` 의
> 프론트 타입이다. 스웨거에서 찾을 이름은 `FrameCreateRequest` / `FrameResponse` 다.

### 2. 프론트는 양방향으로 싣는다

`apps/web/lib/frameApi.ts` 가 소유한다 — 송신 `toCreateFrameRequest`(4개일 때만 싣는다),
수신 `toThemeExportJson`(서버가 안 주면 전부 `false` 로 본다). 규칙은 `frameApi.test.ts` 가 고정한다.
따라서 **저장한 프레임을 다시 열면 누끼 토글이 복원된다.** 2026-06 결정 아래에서 있던
「다시 열면 토글이 초기화된다」 한계는 없어졌다.

### 3. 회원 결과물은 서버가 그리고, `composeFramePng` 은 비회원 전용이다

회원 경로는 `POST /api/auth/user/media/compose` 다. 합성 요청은 `frameId` 로 저장된 프레임을 지목하므로
(`ComposeRequest.frameId`), 위 1·2 로 저장된 `cellCutouts` 가 합성 입력에 실린다.

브라우저 합성(`composeFramePng`)은 호출자가 하나뿐이고 비회원 분기다 —
`apps/web/app/shoot/result/page.tsx` 의 `if (guestMode)`. 백엔드에 비회원 경로 자체가 없어서
(합성·프레임 저장이 전부 `/api/auth/` 아래) 비회원의 결과물은 브라우저가 그린 blob 이 곧 최종본이다.
이 경로에서는 누끼가 결과 이미지에 **구워진다**(`composeFrame.ts` 가 컴포넌트 렌더 뒤 `drawCellCutouts`).

## 미해결: 서버 합성이 누끼를 실제로 **그리는가**

저장·왕복은 확정이지만 **렌더 결과는 이 레포에서 판정이 나지 않는다.** 근거가 갈린다.

- 도는 서버의 스웨거 `FrameCreateRequest.cellCutouts` 설명: 「⚠️ **서버는 이 값으로 아무것도 그리지
  않는다** — 누끼는 프론트가 원본 픽셀에 구워서 업로드해야 한다. 이 토글은 편집기가 저장 프레임을
  다시 열 때 어느 칸이 누끼인지 복원하는 용도다.」
- `docs/backend-contract.md` 의 실측표: 「합성 결과에 반영된다 — 켠 칸만 가장자리가 어두워졌다.」

jar 은 여기서 끝난다. `ComposeSpecAssembler` 가 `Frame.getCellCutouts()` 를 불러 명세에 실어 넘길 뿐,
픽셀을 그리는 곳은 jar 밖 Lambda 다(`LambdaComposeExecutor` → `cloud.aws.lambda.compose-function` /
`COMPOSE_LAMBDA_FUNCTION`).

**이 질문의 소유자는 `docs/backend-contract.md` 다.** 백엔드에 물어 거기 한 곳에서 결론을 내고,
이 ADR 은 그 결론을 인용만 한다. 여기에 답을 복제하면 정정이 ADR 까지 오지 못한다.

## 경위 — 원 결정(2026-06-16)과 그것이 뒤집힌 이유

원 결정은 이랬다.

> 누끼는 클라이언트 시각 효과로 두고 **결과 이미지에 굽는 것**까지만 지원한다.
> 백엔드 요청에 옵셔널 필드로 보내는 시도(`b7d6ac6`)는 백엔드가 미지 필드를 거부하면 프레임 저장
> 자체가 깨질 위험이 있어 채택하지 않는다. **백엔드 스키마 지원이 선행되어야 한다.**

전제였던 「스키마에 필드가 없다」가 그 뒤 두 번의 변화로 무너졌다.

1. **백엔드가 필드를 열었다.** 선행 조건이 충족됐으므로 「보내지 않는다」의 근거가 사라졌다.
2. **결과물을 그리는 주체가 바뀌었다.** 서버 합성으로 넘어가면서 회원 경로의 최종 이미지는 브라우저가
   아니라 서버가 만들게 됐다. 그래서 「결과 이미지에 굽는다」는 원 결정의 유일한 보장 수단이
   회원에게는 성립하지 않았고, 사용자가 고른 누끼는 저장 썸네일에만 남고 결과물에서 사라졌다.
   **못 보낸 게 아니라 안 보낸 것**이었고, `742970a` 가 `frameApi.ts` 를 양방향으로 고쳐 막았다.

중간 정정 두 건도 이 문서에 있었다. `b916432`(2026-06-28)로 동영상 기능이 제거돼 영상 출력 경로 서술이
빠졌고, `bbfdcbf`(2026-08-20)로 `/decorate`·`/upload` 가 사라져 옛 업로드 경로 서술이 대상을 잃었다.
누끼 UI 자체는 `/theme/sticker` 아래에 그대로 있다. (별개 라우트인 `/shoot/upload` 는 살아 있으니
「업로드가 사라졌다」로 읽지 말 것.)
