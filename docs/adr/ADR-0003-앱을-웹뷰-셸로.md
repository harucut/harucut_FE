# ADR-0003 — 앱을 웹뷰 셸로 바꾼다 (ADR-0001 대체)

- 상태: 채택
- 날짜: 2026-08-18
- 대체 대상: [ADR-0001 모바일 확장 전략](./ADR-0001-모바일-확장-전략.md)

## 무엇을 바꿨나

앱이 자기 화면을 그리지 않는다. 웹을 그대로 띄우고, 웹이 못 하는 것만 네이티브가 맡는다.

| | 이전 | 이후 |
|---|---|---|
| 앱 화면 코드 | `screens/` 6,299줄 + components/store/lib 등 11,534줄 | 셸·브리지 약 400줄 |
| 라우트 | 19개(웹의 부분집합) | 1개(`app/index.tsx`) |
| 네이티브가 맡는 것 | 전부 | 사진첩 저장·공유 시트·햅틱·뒤로가기·딥링크 |

## 왜

**앱은 대등한 구현이 아니라 뒤처진 복제본이었다.** 앱 라우트 19개는 전부 웹에 1:1 로 있었고
앱 전용 화면은 하나도 없었다. 반대로 웹에는 핵심 단계인 `/decorate`(네컷 꾸미기)가 더 있었다.

두 벌을 유지하는 비용이 실측으로 드러났다 — 최근 300 커밋 중 웹·앱을 건드린 196개 가운데
**45개(23%)가 같은 변경을 두 번 구현한 것**이었다. 그리고 두 번 만드는 동안 계속 어긋났다:

- 소셜 로그인 로고 크기: 웹 18/20/22px vs 앱 20/26/30px
- 네이버 버튼색: 웹 `#007A3D` vs 앱 `#03C75A` (둘 다 규정 위반이었다)
- 버튼 순서: 웹 구글부터 vs 앱 카카오부터
- 비회원 체험 범위와 안내 문구

웹의 모바일 뷰는 애초에 모바일 우선으로 짜여 있었다 — 기본 컨테이너가 `max-w-md` 이고
`lg:` 에서 데스크톱으로 확장되며, 앱의 하단 5탭과 같은 규격의 `MobileTabBar`(74px 바 +
54px 촬영 FAB)가 이미 있었다. 즉 "앱처럼 보이는 웹"이 이미 존재했다.

## ADR-0001 을 뒤집는 이유

ADR-0001 은 "웹이 브라우저 전용 API(react-konva, Canvas, getUserMedia)에 깊게 의존해서
앱 UI 를 따로 설계한다"고 적었다. 그 전제가 반대로 뒤집혔다 — **그 브라우저 API 들이
WebView 안에서 그대로 돈다.** 따로 설계할 이유가 아니라 웹을 그대로 쓸 이유가 됐다.

## 경계선

네이티브에 남기는 것은 **웹이 할 수 없는 것**뿐이다.

- **사진첩 저장** — 웹 표준에 사진첩 쓰기 API 가 없다. WebView 에서는 `<a download>` 가
  조용히 아무 일도 안 한다(안드로이드는 download 속성 무시 + blob 은 DownloadListener 로도
  못 받음, iOS 는 저장 UI 자체가 없음).
- **공유 시트** — 안드로이드 WebView 에 `navigator.share` 가 없다.
- **햅틱** — 웹 `navigator.vibrate` 는 iOS 에서 동작하지 않는다.
- **하드웨어 뒤로가기** — 셸이 처리하지 않으면 어느 화면에서든 앱이 통째로 닫힌다.
- **딥링크(`harucut://`)** — 소셜 로그인 복귀 경로.

프로토콜은 `apps/web/lib/nativeBridge.ts` ↔ `apps/mobile/lib/native-bridge.ts` 한 쌍이다.
바꾸려면 양쪽을 같이 고쳐야 한다.

## 카메라를 네이티브로 되돌릴 여지

촬영은 지금 WebView 안의 `getUserMedia` 가 한다. 화질 천장은 이쪽이 낮다 —
합성 캔버스가 4000×6000(24MP), 슬롯 1700×2400(4.08MP) 규격인데 `getUserMedia` 는
안드로이드 최선에서도 컷당 1.65MP 다.

다만 **이 전환이 화질을 떨어뜨리지는 않는다.** 이전 앱은 최종 결과물을
`captureRef(미리보기 View)` 로 만들었고, 그건 화면 해상도에 묶여 있었다(기기가 작을수록 낮음).
즉 네이티브 카메라의 이점을 이전 앱도 실현하지 못하고 있었다.

화질을 실제로 올리려면 촬영만 네이티브로 되돌리면 된다. 브리지에 `openCapture` 를 추가하고
결과를 웹으로 돌려주는 형태다. 그때는 `expo-camera` 를 다시 넣되
`takePictureAsync({ quality: 1 })` + `pictureSize` 지정 + `skipProcessing` 미사용이어야 한다
(`skipProcessing: true` 면 quality 가 무시되고 EXIF 방향이 깨진다 — 이전 코드의 실수였다).

## 아직 열려 있는 것

`docs/app-shell-backend-requests.md` 참고. 요약하면 백엔드에 두 가지가 필요하다.

1. **OAuth 세션을 앱으로 넘기는 일회용 코드** — 없으면 앱에서 구글 로그인이 불가능하다
   (구글이 임베디드 웹뷰를 `disallowed_useragent` 로 차단한다). 카카오·네이버는 지금도 된다.
2. **비회원·행사 참가자용 합성 경로** — 서버 합성이 전부 인증 경로 아래라,
   "참가자는 가입 없이 찍고 그 자리에서 가져간다"는 판매 문구가 서버 합성 전환 시 깨진다.
