# ADR-0001 모바일 확장 전략

## 상태

승인

## 결정

- 기존 Next.js 웹 앱은 루트에 그대로 유지한다.
- 모바일 앱은 `apps/mobile` Expo 앱으로 별도 추가한다.
- 브랜치 승격은 `develop_loop -> develop -> main`을 유지한다.
- `main`, `develop`, `develop_loop`에는 직접 commit/push 하지 않는다.
- Ralph 자동화는 issue 브랜치와 push까지는 허용하지만 PR은 자동 생성하지 않는다.

## 이유

- 웹을 바로 `apps/web`로 옮기면 초기 리스크가 크다.
- 현재 웹은 브라우저 전용 캔버스/비디오 파이프라인이 강해서 모바일 UI를 새로 설계하는 편이 낫다.
- 앱 기본 골격을 먼저 만들고, 공통 자산은 이후 `packages/*`로 점진적으로 분리하는 편이 현실적이다.

## 결과

- 웹은 거의 그대로 유지된다.
- 모바일은 독립적으로 빠르게 시작할 수 있다.
- Ralph loop와 GitHub 보호 규칙은 두 플랫폼 공통 운영 계층으로 유지된다.
