# ADR-0001 모바일 확장 전략

## 상태

확정

## 결정

- 기존 Next.js 웹 앱은 `apps/web`에서 유지한다
- 모바일 앱은 `apps/mobile` Expo 앱으로 별도 확장한다
- 브랜치 승격은 `develop_loop -> develop -> main`을 따른다
- `main`, `develop`, `develop_loop`에는 직접 commit/push하지 않는다

## 이유

- 웹에 바로 모바일 흐름을 얹으면 초기 리스크가 커진다
- 현재 웹은 브라우저 전용 인터랙션 비중이 높아 모바일 UI를 별도로 설계하는 편이 맞다
- 기본 구조를 먼저 만들고 공통 자산은 이후 `packages/*`로 점진 분리하는 편이 안정적이다

## 결과

- 웹은 기존 구조를 유지한다
- 모바일은 독립적으로 빠르게 시작할 수 있다
- 브랜치 보호와 배포 흐름은 공통 운영 규칙으로 유지한다
