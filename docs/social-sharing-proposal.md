## 0. 한 줄 요약

harucut은 지금 **"혼자 만드는 네컷"** 이다. 셋로그가 증명한 건 **"떨어져 있어도 친구와 같은 순간을 함께 기록한다"** 는 욕구다. 이 욕구를 네컷이라는 우리 포맷에 얹으면, harucut은 **"친구들과 한 칸씩 채워 완성하는 오늘의 네컷"** 이라는 고유한 소셜 경험을 만들 수 있다.

---

## 1. 배경 — 왜 지금 이 논의를 하나

### 1.1 현재 harucut의 위치

코드/문서 기준으로 본 현재 제품:

- **포맷**: 디지털 인생네컷(포토부스) 메이커. 8장 촬영 → 4장 선택 → 프레임·스티커 합성 → PNG 내보내기.
- **흐름**: `/shoot`(촬영) · `/upload`(업로드) · `/theme`(프레임 편집) · `/history`(보관) · `/mypage`.
- **공유의 형태**: 결과물을 *완성한 뒤* 카메라롤로 내보내 외부(인스타·카톡)로 보내는 **단방향·앱 밖 공유**.
- 즉, 제작은 철저히 **개인 작업**이고, "친구"는 결과물을 받는 수신자일 뿐 제작 과정에 들어오지 않는다.

### 1.2 시장 신호 — 셋로그가 보여준 것

- 출시 후 빠르게 **누적 200만 / 일평균 194만** 사용자, **10~20대 93%**.
- 성공의 본질은 기능이 아니라 **관계의 포맷**이다: "잘 나온 컷을 고르고 꾸미는" 기존 SNS 피로감의 반대편에서, **꾸미지 않은 현재 + 친한 친구만(폐쇄형) + 동시성**을 판다.
- 업계 평가: 인스타 *대체*가 아니라 **보완 도구**. → 우리에게 시사점: harucut도 거대 SNS와 싸울 필요 없이, **"친구 단위 폐쇄형 공동 창작"** 이라는 빈 자리를 노릴 수 있다.

> 주: 사용자가 말한 "셀로그"는 정황상 이 **셋로그(Setlog)** 를 가리키는 것으로 보고 분석했다. (사진일기 계열 "디로그", 비밀일기 "Seclog" 등 유사 이름 서비스가 있으나 "친구와 같이 하루를 만든다"는 묘사에 정확히 맞는 건 셋로그.)

## 2. 셋로그(Setlog) 완전 분석

### 2.1 제품 정의

매시간 알림에 맞춰 **2~3초 실시간 클립 + 짧은 캡션**을 찍으면, 시스템이 하루치를 모아 **자동으로 미니 브이로그**로 편집해 주는 소셜 영상 앱.

### 2.2 핵심 메커니즘 (작동 구조)

| 구성 요소 | 내용 |
| --- | --- |
| **Log(방) 생성** | 우상단 `+`로 Log 생성 → 초대 코드로 친구 합류 |
| **폐쇄형 그룹** | 최대 12명. 친한 지인만 들어오는 **닫힌 구조** |
| **시간 트리거** | 매시간 푸시 알림 → 그 타이밍에 다 같이 촬영 |
| **실시간성 강제** | 기존 영상 업로드 불가, 과거 시간대 촬영 불가 — **"지금"만 기록** |
| **동시 시청** | 분할 화면으로 친구 클립을 실시간 확인 |
| **상호작용** | 댓글·이모지 반응, 업로드 시 즉시 알림 |
| **자동 완성** | 하루 끝나면 클립들이 자동 편집된 한 편의 영상으로 |
| **내보내기** | 카메라롤 저장 (앱 내 음악·고급 편집은 없음 → 외부 앱 연계) |

### 2.3 인기 요인 (왜 먹혔나)

1. **진정성**: 보정·셀렉 압박 제거. "지금 모습 그대로"가 오히려 편함.
2. **동시성(함께 있음)**: 같은 시각, 다른 장소 → "떨어져 있어도 같이 시간 보내는" 유대감.
3. **폐쇄성**: 불특정 다수의 시선이 없음 → 심리적 안전. 좋아요 경쟁 없음.
4. **무편집 자동 완성**: 결과물 제작에 드는 노력이 0에 수렴 → 진입장벽 최저.
5. **수집/완성 욕구**: 하루가 "한 편"으로 닫히는 리추얼.

### 2.4 한계 (우리가 파고들 틈)

- 영상 중심 → **무겁고**, 매시간 촬영은 **피로**할 수 있음(번아웃 가능성).
- 앨범처럼 **두고두고 꺼내 보는 정적 결과물**이 약함(영상은 한 번 보고 끝나기 쉬움).
- 꾸미는 재미·**소장각 결과물**이 거의 없음 — 이게 정확히 네컷의 강점.

## 3. 셋로그 vs harucut — 포지셔닝

| 축 | 셋로그 | 현재 harucut | 함의 |
| --- | --- | --- | --- |
| 결과물 | 자동편집 영상(흐름) | 네컷 이미지(완성품) | **소장·전시**는 우리가 우위 |
| 제작 주체 | 친구 공동(동시) | 개인 | **여기가 빈칸** ← 핵심 기회 |
| 꾸미기 | 거의 없음 | 프레임·스티커 강함 | **공동 꾸미기**로 차별화 가능 |
| 공유 시점 | 제작=공유 (실시간) | 완성 후 앱 밖 | **앱 안 공유 루프** 부재 |
| 관계 모델 | 폐쇄형 그룹(≤12) | 없음(개인 계정) | **그룹/친구 개념 도입 필요** |
| 리추얼 | 매시간 → 하루 1편 | 없음 | **데일리 리추얼** 도입 여지 |

**결론**: 셋로그를 그대로 베끼면(영상·매시간) 우리 강점(소장각 네컷·꾸미기)을 버리는 셈. 우리는 **셋로그의 "관계·동시성·폐쇄성·리추얼"만 차용**하고, **결과물은 네컷 그대로** 가져가야 한다.

## 4. 기능 제안 — "함께 만드는 네컷"

아래는 컨셉 후보들이다. ⭐가 핵심 추천.

### ⭐ 4.1 컨셉 A: "한 칸씩 채우는 공동 네컷" (Co-op Cut)

네컷의 **4칸을 친구들이 나눠 채운다.** 네컷 포맷과 가장 자연스럽게 붙는 우리만의 형태.

- **방 만들기**: 한 명이 프레임을 고르고 방을 연다 → 초대 링크/코드로 친구 합류(2~4명).
- **칸 배정**: 각자 자기 칸을 맡아 촬영/업로드. 1번칸=A, 2번칸=B…
- **실시간 채움**: 친구가 칸을 채우면 다른 사람 화면에 즉시 반영("OO이 2번칸 완성!").
- **공동 완성**: 4칸이 다 차면 **하나의 네컷이 완성** → 참여자 전원 히스토리에 동시 저장.
- **변형**:
  - *릴레이 모드*: 순서대로 한 칸씩(앞 사람 컷을 보고 컨셉 이어가기).
  - *동시 모드*: 같은 시각 다 같이 찍기(거리 두고도 "같이 찍은 네컷").

> 왜 강한가: 셋로그의 "함께/동시"를 우리 포맷에 **1:1로 매핑**. 결과물이 **소장 가능한 한 장**으로 남아 영상보다 재방문성이 높다.

### ⭐ 4.2 컨셉 B: "데일리 한 컷, 모여서 네컷" (하루컷 본래 의미 살리기)

브랜드명 *하루컷*의 의미를 제대로 살리는 리추얼형.

- 친구 그룹이 **하루 1컷씩** 찍어 적립.
- **4일이 모이면 한 네컷**이 자동 완성(또는 4명이 같은 날 1컷씩 → 그날의 네컷).
- 그룹 페이지에 **네컷 스트립이 일자별로 쌓이는 아카이브**.
- 주간/월간 "우리 그룹 네컷 모음" 자동 생성.

> 왜 강한가: 셋로그의 매시간 피로감을 **하루 1회**로 낮춰 지속가능. 브랜드 정체성과 정확히 일치.

### 4.3 컨셉 C: 폐쇄형 친구 그룹 + 피드

- 셋로그식 **닫힌 그룹**(초대제, 좋아요 수 비공개).
- 멤버가 완성한 네컷이 그룹 내부 피드에 뜸 → **이모지 반응·짧은 댓글**.
- 외부 공개 없음 → 심리적 안전. "우리끼리 보는 네컷 일기장".

### 4.4 컨셉 D: 공동 프레임/테마 꾸미기

- 한 네컷을 **여러 명이 같이 꾸민다**: A가 사진 배치, B가 스티커, C가 문구.
- 우리의 강점인 `theme`(프레임·스티커) 편집을 **협업 캔버스**로 확장.
- 셋로그엔 없는 영역 → **명확한 차별점**.

### 4.5 부가 장치 (어느 컨셉이든 얹을 수 있음)

- **반응/리액션**: 칸/네컷 단위 이모지.
- **동시 촬영 룸**: 같은 방 인원이 카운트다운에 맞춰 동시에 셔터.
- **알림**: "친구가 칸을 채웠어요", "오늘의 하루컷 찍을 시간".
- **공동 히스토리**: 함께 만든 네컷은 참여자 전원에게 저장(소유권 공유).
- **위젯/공유 카드**: 완성 네컷을 카톡/인스타로 보낼 때 "OO·OO와 함께 만듦" 크레딧 라벨.

## 5. 추천안 & MVP 우선순위

**핵심 추천: 컨셉 A(한 칸씩 채우는 공동 네컷)를 메인으로, 컨셉 B(데일리 적립)를 리텐션 장치로.** C·D는 후속.

| 단계 | 범위 | 목표 | 비고 |
| --- | --- | --- | --- |
| **MVP** | 방 생성 + 초대코드 + 칸 배정 + 비동기로 4칸 채워 완성 + 공동 저장 | "친구와 한 네컷을 같이 완성"의 검증 | 실시간 미반영, 새로고침 기반이어도 OK |
| **v1** | 실시간 칸 채움 알림 + 이모지 반응 | 동시성·상호작용 체감 | |
| **v2** | 폐쇄형 그룹 + 내부 피드 + 데일리 적립 아카이브(컨셉 B) | 리텐션·리추얼화 | |
| **v3** | 동시 촬영 룸(카운트다운 동시 셔터) + 공동 꾸미기(컨셉 D) | 차별화 심화 | |

**처음부터 하지 말 것**: 매시간 알림(피로), 영상 자동편집(우리 강점 아님), 공개 피드(폐쇄성 강점 훼손).

## 6. harucut만의 차별화 포인트 (셋로그가 못 가진 것)

1. **소장각 결과물**: 영상은 흘러가지만 네컷은 **벽에 거는 한 장**. 공동 제작물이 오래 남는다.
2. **꾸미는 재미**: 프레임·스티커 편집 자산을 **공동 창작 캔버스**로 확장 가능.
3. **저부담 리추얼**: 매시간이 아니라 **하루 1컷** → 지속가능, 브랜드와 일치.
4. **명확한 완성감**: "4칸이 다 찼다"는 닫힘이 셋로그의 모호한 흐름보다 만족도가 큼.

## 7. 제품·기술 고려사항 (현 구조 기준, 구현은 별도)

> 코드 변경 없이, 향후 설계 시 미리 짚을 점만 메모.

- **데이터 모델**: 지금은 개인 결과물 중심. **"방(Room)/세션 + 멤버 + 칸(slot)별 소유자"** 개념과, **공동 소유 히스토리**가 새로 필요.
- **기존 흐름 재사용**: `/shoot`의 8장→4장 로직, `frameId`/`draftId` 세션, `theme` 편집기는 **칸 단위로 재활용** 가능. "4칸 선택" 규칙을 "내 칸 1개 채우기"로 축소 적용.
- **상태관리**: 현재 zustand 도메인 스토어(shoot/upload/theme/library/session) 구조에 **room/collab 스토어**가 추가되는 형태가 자연스러움.
- **실시간성**: MVP는 폴링/새로고침으로 충분. v1부터 WebSocket/SSE 또는 푸시로 "칸 채움" 이벤트.
- **인증/초대**: 이미 세션·소셜로그인이 있음 → **초대 링크(딥링크)·게스트 합류** 정책 결정 필요(앱 미설치자 처리).
- **권한/프라이버시**: 공동 네컷의 **저장·삭제·재공유 권한**, 멤버 탈퇴 시 결과물 처리 규칙.
- **모바일 우선**: 동시 촬영·푸시 알림은 모바일(Expo) 강점 영역. 웹은 열람·공유 중심으로 역할 분담 가능.

## 8. 리스크 & 주의

- **콜드스타트**: 친구가 같이 안 깔면 가치 0인 네트워크형 기능. → 초대 마찰 최소화 + **1인도 의미 있는 fallback**(혼자 4칸 다 찍기) 유지가 필수.
- **모방 함정**: 셋로그를 그대로 따라가면(영상·매시간) 우리 강점을 버리고 후발 열위가 됨.
- **프라이버시**: 공동 소유 콘텐츠는 분쟁 소지. 권한·삭제 정책을 기능보다 먼저 합의.
- **피로도**: 알림·리추얼은 양날의 검. **하루 1회·옵트인**을 기본값으로.
