# 모바일 QA 체크리스트

Ralph loop가 `apps/mobile` 작업을 완료로 판단하기 전에 아래를 직접 확인합니다.

## 범위

- `apps/web`는 수정하지 않는다.
- 모바일 변경은 `apps/mobile` 안에서만 진행한다.
- 웹은 기준선 확인용으로만 본다.

## 화면 확인

- `home`
  - 첫 화면 진입이 자연스럽다
  - 핵심 CTA가 바로 보인다
  - 텍스트가 잘리지 않는다
- `shoot`
  - 카메라/권한 유도 문구가 명확하다
  - 버튼 배치가 한 손 사용 기준으로 무리 없다
- `upload`
  - 업로드 진입 경로와 상태 표시가 명확하다
  - 실패 시 재시도 흐름이 보인다
- `history`
  - 빈 상태와 데이터 상태 모두 자연스럽다
  - 카드/리스트 가독성이 유지된다
- `mypage`
  - 계정/설정/로그아웃 흐름이 명확하다
  - API Base URL 등 개발용 정보가 사용자 화면을 망치지 않는다

## 디자인 확인

- safe area가 깨지지 않는다
- 상단/하단 여백이 어색하지 않다
- 텍스트 잘림, 겹침, 버튼 밀림이 없다
- 색 대비가 충분하다
- 탭/버튼 터치 영역이 너무 작지 않다
- 로딩, 빈 상태, 에러 상태가 시각적으로 붕 뜨지 않는다

## 통신 확인

- 인증 또는 세션 확인 흐름이 연결된다
- 업로드/전송 관련 요청이 기대한 엔드포인트로 나간다
- 히스토리/마이페이지 조회가 정상 응답 또는 정상 에러를 처리한다
- 실패 시 사용자 메시지가 이해 가능하다
- 네트워크가 없거나 서버가 죽었을 때도 화면이 망가지지 않는다

## 완료 규칙

- 직접 확인하지 않은 기능을 "정상"이라고 쓰지 않는다
- 통신을 실제로 확인하지 못했으면 부족한 조건을 명시한다
- 디자인 검증 없이 기능만 맞아도 완료 처리하지 않는다
