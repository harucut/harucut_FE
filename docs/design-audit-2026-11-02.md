# 디자인 검수 (2026-11-02)

2026-09-06 검수 뒤에 생긴 화면(참가·부스·결과·Studio·CMS)이 대상이다. 그 뒤 그 자리에서 고쳤다. 아래 「판정」은 고치기 **전**이고, 고친 뒤 독립 재평가는 「고친 뒤 다시 본 것」에 있다.

## 어떻게 봤나

- **평가 둘을 따로 돌렸다.** A: 스크린샷과 소스를 읽는 디자인 디렉터 평가(Nielsen 10개, 인지 부하, 감정 여정, 페르소나). B: `detect.mjs`, 브라우저 오버레이, 실측(터치 영역·넘침·포커스 링), Web Interface Guidelines, em-dash 집계. 서로의 결과를 보지 않았다.
- **로컬 전체 스택으로 눌러 봤다.** 실제 백엔드(Flyway·validate), 실제 합성 코드(ComposeHandler), S3·SQS·Lambda 대역, Playwright Chromium. 카메라는 사진을 내보내는 가짜 카메라다. **실기기·실제 AWS 는 아니다.**
- 폭은 390(휴대폰), 820×1180(세로 부스), 1280×800(가로 부스), 1280·1440(데스크톱).

## 판정 (고치기 전)

Nielsen **17/40**(Poor). 표면별 어림치: 참가 21, CMS 20, Studio 15, 부스 14. 가장 아팠던 것:

- 행사 쪽이 제품에 뿌리내리지 못했다. 참가 화면은 로고·제목·알약의 반복이고, 부스는 폰 화면을 576px 로 태블릿에 띄운 것이고, Studio 는 6,546px 한 장의 설정 폼이었다.
- 2026-09 검수가 근거까지 남긴 뷰파인더 문법(숫자는 얼굴 밖, 찍힌 순간 플래시)을 행사 흐름이 가져오지 않았다.
- 끝 구간이 사진을 놓쳤다. 만들기를 누르면 테마 없는 「사진을 찾고 있어요」가 뜨고, 저장은 탭을 서명 URL 로 옮겼다.
- 주최자가 Studio 로 들어갈 길이 없었다. 공유 이미지에는 타사 브랜드가 적혀 있었고, 기본 스티커 39개는 디자인 도구 팩이었다(출처 불명, 39MB).

## 브랜드를 다시 정했다

사용자 지시로 로고·색·스티커·앱 화면을 Codex 시안과 지금 것을 비교해 골랐다.

- **색:** 실제 화면에 네 후보(지금 초록, 형광 라임, 암실 주홍, 핫 핑크)를 CSS 변수로 입혀 찍어 비교했다. **라임 #C8F135** 로 정했다. 검정 위의 #1ED760 은 그대로 Spotify 의 얼굴이고 네이버 초록과도 겹쳤다. 주홍은 오류 색과 부딪히고, 핑크는 결혼식·기업 행사에서 한쪽으로 기운다. 라임은 피부색과 겹치지 않아 사진이 산다. 라이트에서는 면 채움만 라임이고 글자·선은 #4C5F00 이다(대비는 DESIGN.md).
- **로고:** 시안 6개 중 **ㅎ** 으로 정했다. 위 획은 셔터, 긴 획은 카메라 윗면, 동그라미는 렌즈, 안의 점만 라임이다. 예전의 초록 네 줄은 작게 보면 배터리처럼 읽혔다. 시안 이미지를 쓰지 않고 SVG 좌표로 다시 그렸다(`packages/shared/src/brand-mark.ts`). 웹·앱 아이콘은 `scripts/gen-brand-icons.mjs` 로 한 번에 굽는다.
- **스티커:** 광택 클립아트 묶음을 버리고 납작한 하루컷 묶음 30개로 바꿨다([frame-assets.md](./frame-assets.md)).
- **앱 화면:** 시안에서 「사진이 주인공」인 구성을 가져왔다(홈, 프레임 선택, 결과, 기록).

되돌리려면 색은 `globals.css` 토큰, 로고는 `brand-mark.ts` 와 생성기로 충분하다. **앱 아이콘이 바뀌었으니 다음 앱 빌드에 들어간다.** 스토어 등록 이미지는 사용자 몫이다.

## 고친 뒤 다시 본 것

앞선 평가를 보지 않은 평가자가 고친 화면의 스크린샷과 소스로 다시 봤다. Nielsen **26/40**(Acceptable). 표면별 어림치: 개인 앱 29, 참가 28, 부스 27, Studio 25, CMS·편집기 19. 그때 나온 우선 문제와 처리는 아래다. 처리 뒤 점수는 다시 매기지 않았다.

| 문제 | 처리 |
|---|---|
| 합성 실패가 막다른 길이었다 | 고침. 방금 찍은 사람은 「다시 찍기」, 링크로 받은 사람은 「다시 확인」과 행사장에서 다시 찍으라는 안내. 부스는 빈 QR 을 치우고 「처음으로」 |
| 동의문은 90일, 결과는 30일로 어긋나도 게시됐다 | 고침. 어긋나면 게시 확인에서 체크해야 게시된다. 일수가 하나면 「동의문을 N일로 고치기」 |
| 입구와 부스 대기의 주인공이 회색 칸이었다 | 고침. 프레임 그림을 칸이 뚫린 PNG 로 굽고, 아래에 예시 사진을 깐다(「예시 사진」 표기) |
| 합성 대기가 빈 카드였다 | 고침. 방금 찍은 네 장을 프레임에 넣어 보여 준다. 새로고침하면 칸 모양의 자리만 남는다. 예상 시간은 실측 전이라 적지 않았다 |
| 재촬영이 원본을 바로 버렸고, 「한 장 찍기」 위에 네 장을 찍는다고 썼다 | 고침. 새 사진이 찍혀야 버린다. 「그대로 둘게요」로 돌아간다. 문구 미리보기에 내 사진이 들어간다 |
| 부스 세로 결과에서 사진이 QR 보다 훨씬 작았다 | 고침. 세로로 긴 프레임은 세로 태블릿에서도 사진과 QR 을 나란히 둔다 |
| Studio·CMS 가 개인 앱 옷을 입고 있었다 | 고침. 위쪽 메뉴에서 기록·요금제를 뺐고 로고와 행사 이름의 좌변을 맞췄다. 활동 기록의 코드값과 행사 id 를 말로 바꿨다 |
| 편집기가 설정 폼 같았다 | 대부분 고침. 「토글」「캔버스 칸 탭」 문구를 고치고 삭제를 맨 아래로 옮겼다. 캔버스 열을 넓히고 스크롤해도 따라오게 했다. 칸 안에 예시 사진을 깔고 끌 수 있다. 도구 밀도는 그대로다 |
| 칸 위 글자가 사진에 묻히거나 칸 밖으로 나가도 경고가 없다 | 안 고침. 지금 기본값(아래 여백·읽히는 색)이면 생기지 않고, Studio 미리보기에서 예시 사진으로 보인다 |

이때 **입구의 테마 검증이 무효였다는 것**도 나왔다. 첫 화면을 서버 렌더로 바꾼 뒤로 응답 가로채기가 먹히지 않아, 테마 스크린샷이 기본 화면 그대로였다. Studio 에서 프리셋을 저장·게시한 뒤 `/e` 를 여는 방식으로 다시 봤고, 다크·아이보리·가을 프리셋이 서버 렌더에 적용되는 것을 확인했다.

## 남은 것

- **실기기:** iOS 저장 동작, 인앱 브라우저, 상태바, 터치 드래그, 부스 거리 가독성(1.5m 계산값뿐), 실제 인쇄.
- **백엔드 필드로 해결한 것:** 재방문 썸네일·공간 이름·저장과 게시의 차이·고객 행 사진 수(BE fork #46), 행사 문의처(`copy.contact`). 문의처는 합성 실패·기간 지남·촬영 시간 아님 화면에 주최자가 적었을 때만 나온다.
- **결정이 필요한 것:** 비화이트라벨 행사에 하루컷 표시를 넣을지(지금 참가 화면은 언제나 하루컷 표시가 없어, `하루컷 표시 숨기기` 는 차이가 없다). AI 예시 이미지의 표시 범위.
- **안 고친 것:** 활동 기록 필터, 기록 카드의 삭제 위치. 랜딩·요금제의 큰 제목 크기가 글자 단계 밖이다(탐지기 23건, 이번 범위 밖). 편집기 이동은 `Link` 가 아니다(메모리 상태라 새 탭에서 깨진다). 부스 대기 화면 전체를 버튼으로 만들지는 않았다.
